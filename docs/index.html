What MiniCon is

One file

The executable is the whole product. Nothing installs, nothing runs in the background. Delete the file and it's gone.

Small, verified

All six target artifacts are checked; Windows additionally gates its PE import table to OS libraries. Every size shown is measured.

Small ≠ toy

Real PTY, real VT parsing, tabs, IME, mouse, scrollback — small is the size, not the feature list.

This is the whole application.

A tab column, a terminal, an input line. That's it.

It runs where modern terminals cannot.

Windows Terminal needs build 17763, and so does ConPTY. Your Server 2016 box has neither. MiniCon doesn't care — it finds the pseudoconsole at run time, or hosts the shell itself.

01 / NO DEAD END

A missing API is not a dead program

The pseudoconsole entry points are resolved at run time. Imported statically, one missing symbol stops the program before it starts.

02 / ITS OWN FALLBACK

No ConPTY? It hosts the shell itself

MiniCon re-executes itself to host your shell in a hidden console and reads the screen buffer. That agent is MiniCon — no second binary.

03 / CAPABILITY, NOT VERSION

It asks the system, not a table

The backend is chosen by whether the exports exist. Version numbers are only for the message you read.

05 / SELF-DESCRIBING

It tells you what it got

`--status` reports the backend this machine selected and why, the font the system resolved to, and where failures are written. It opens no window.

04 / NO REDISTRIBUTABLE

Nothing to install first

The VC runtime is linked in. A test parses the import table and fails on anything outside Windows' own set.

A place to type that is not the output.

Most terminals make you type into the same region a program is printing into — so a long command and a burst of output get tangled. MiniCon gives input its own area.

01 / NO COLLISION

Compose while it scrolls

Write a long command while output keeps arriving. Nothing you type interleaves with anything a program prints.

02 / RECALL

A sent line survives being sent

Up and Down walk what you sent before. Half-typed text is kept while you browse.

03 / IT SAYS WHERE

Named, not numbered

The label names the tab the text is going to. In a tab tree, that's the difference between confidence and a guess.

A terminal your scripts can see into.

Sending a keystroke is easy and blind. MiniCon's control CLI reads back what the window actually shows — text, screenshots, focus, tabs — so automation waits on a real condition, not a timer. And it's all local: a named pipe on Windows or a Unix socket on Linux and macOS, with no server or cloud.

# start a session with a local control endpoint
minicon --control unix:/tmp/minicon-build/control.sock
# Windows: minicon --control pipe:\\.\pipe\build

# run something, then wait for it — no sleeps
minicon cli --control unix:/tmp/minicon-build/control.sock send-text "cargo test\r"
minicon cli --control unix:/tmp/minicon-build/control.sock wait-text --timeout-ms 600000 "test result"

# read the result as text, or as a picture
minicon cli --control unix:/tmp/minicon-build/control.sock capture-pane
minicon cli --control unix:/tmp/minicon-build/control.sock screenshot-pane --output run.png
ui-snapshot
Focus, IME state, input, pending work, geometry — as JSON.
wait-text · wait-tab-exit
Block until the condition holds or the timeout expires, and say which.
send-keys · send-mouse · send-wheel · send-ui-ime
Named keys, pointer events in cells, scrolling, IME preedit — the same paths a person's input takes.

MiniCon is the terminal. AgenTerm is the Agent-era workbench.

Same platform layer, different job. MiniCon is one file and one window. AgenTerm is what you run when a session must outlive that window — Fleet, mux, persistence, Agent permissions.

MiniCon
Local conhost: PTY, tabs, composer, IME. Automation is --control on a Unix socket or named pipe inside that GUI process. Close the window and the endpoint is gone. No daemon, no default port, no remote.
AgenTerm
The Agent-era upgrade on the same rendering and input-area design: a workbench whose server identity can outlive one terminal. Shared verb spellings, different wire and lifetime.

Getting it

Download a native archive or the experimental unsigned minicon.com and run it—there is no separate installer or bundled language runtime. Linux binaries embed the runtime-only X11 bridge and its XCB-XKB dependency; no -dev package is required.

Latest release Build from source 
# or build it yourself
git clone https://github.com/partnernetsoftware/minicon
cd minicon
cargo build --release   # target/release/minicon[.exe]
