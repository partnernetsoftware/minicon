# v0.1.14 release history

Status: **released.** Public Release `v0.1.14` is published (not a draft). It
carries two Windows fixes — crisp text on scaled displays (per-monitor DPI
awareness) and mouse-wheel scrolling in terminal programs — and stays
dual-signed (Windows Authenticode + macOS Developer ID / notarization).

(Backfilled during the 0.1.15 release to close the archive gap.)

## What shipped

- **Crisp text on scaled Windows displays.** MiniCon now declares per-monitor
  DPI awareness before the first window, so Windows no longer bitmap-stretches
  the window on a display scaled above 100%. The modern APIs
  (`SetProcessDpiAwarenessContext`, `SetProcessDpiAwareness`) are resolved via
  `GetProcAddress` so the binary still loads on Server 2016 / 1607 where they are
  absent; a per-monitor-v2 application manifest is embedded as the declarative
  path. Load-portability guards were added for both dynamic imports.
- **Mouse-wheel scrolling in Windows terminal apps.** The native pixel window's
  `WM_MOUSEWHEEL` (screen coordinates, no cursor position) now reuses the last
  `WM_MOUSEMOVE` point (falling back to `ScreenToClient`), so the wheel report
  carries the hovered cell. Scrolling inside a full-screen mouse-tracking program
  and over the tab sidebar now works on Windows as on macOS / Linux.

## Follow-up

0.1.14's DPI-awareness change (rendering at the real scale instead of a stretched
1.0) exposed a pre-existing layout arithmetic bug — the terminal's bottom row
overlapping the composer, and clicks on a program's bottom input line being
eaten by the composer. Both were fixed in `v0.1.15`; see
[v0.1.15-release-history.md](v0.1.15-release-history.md).
