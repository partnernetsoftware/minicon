## What shipped (the fix — one root cause, two symptoms)

`content_bottom_px` (the height reserved at the window bottom for host UI) had
reserved only the composer since the initial scaffold, omitting the 24-DIP
status bar stacked beneath it. The terminal grid therefore extended one row into
the composer's rect:

- **Symptom 1 — overlap.** The terminal's bottom row overran the composer's top
  edge. Masked while Windows ran DPI-unaware (rendered at scale 1.0, then
  OS-stretched); once 0.1.14 declared per-monitor DPI awareness the
  `status_height * scale` overlap became visible.
- **Symptom 2 — click not forwarded.** Because that overrun row's pixels fell
  inside the composer's hit rect (host-UI hit-testing runs before the terminal),
  a click on a mouse-tracking full-screen program's bottom input line was
  captured by the composer instead of forwarded to the program.

Fix: a single-source `ui::bottom_inset(scale)` reserves composer **+** status, so
the terminal viewport bottom lands exactly on the composer top. Confirmed on the
native ARM64 Windows window via the new `ui-snapshot` geometry: viewport bottom
== composer top == 441, composer flush on status (537), status to frame bottom
(561).

Also added (the "stop finding bugs one at a time" ask): cross-scale layout /
hit-test invariant tests (band tiling, "last terminal row never captured by host
UI", no-overflow, composer sub-control containment, cell<->logical round-trip at
scales 1.0-2.5), a machine-verifiable `geometry` object in `ui-snapshot` (frame,
scale, terminal viewport, composer/status bands, grid) sourced from live window
metrics, and an end-to-end black-box test asserting the viewport/host-UI seam on
a real host.

## Lessons

- **The Defender court receipt carries a UTF-8 BOM.** It is written from the
  Windows guest, so a plain `json.load` on the raw bytes fails with "Unexpected
  UTF-8 BOM"; decode with `utf-8-sig` for ad-hoc inspection. The real
  `reputation_court.py qualify`/`verify` tools handle it — only a hand-rolled
  inspection script tripped. Not a flow bug.
- **Layout is now verifiable without a GPU.** The headless session-0 Windows
  court never presents a frame (0 frames, screenshots can't rasterize), which
  blocked pixel confirmation. Exposing geometry in `ui-snapshot` (sourced from
  live window metrics, not paint-time fields) made the viewport/composer seam
  checkable numerically on that same court — the durable way to "test layout in
  UTM" going forward. See the release-safety and UX-testing memories.
