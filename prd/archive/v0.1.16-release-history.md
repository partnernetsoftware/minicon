# v0.1.16 release history

Status: **released.** Public Release `v0.1.16` is published (not a draft, not a
pre-release). It makes the macOS download double-clickable by shipping a real
application bundle, and adds `install-cli` so the same install still gives a
usable `minicon` command. Dual-signed as always (Windows Authenticode + macOS
Developer ID / notarization).

## What shipped

**macOS now ships `MiniCon.app`.** The problem, measured on v0.1.15: minicon
shipped a bare Mach-O, which **cannot be stapled** (Error 73 — the signing
receipt recorded `stapled=false`), and which Gatekeeper's GUI-launch path
rejects outright — `spctl -a -t exec` answers *"the code is valid but does not
seem to be an app"* **even when the binary is executed from inside a stapled,
notarized `.dmg`**. A double-click therefore raised "Apple could not verify this
app is free of malware", although the binary was genuinely Developer ID signed
and Apple-notarized.

`macos-signing.yml` now assembles `MiniCon.app` (`Info.plist` +
`Contents/MacOS/minicon`), signs it inner-out with hardened runtime and a secure
timestamp, notarizes it, **staples the bundle**, and asserts
`spctl -a -t exec` is `accepted` with `source=Notarized Developer ID` before
placing it in the `.dmg`.

Deliberate design choice: **asset names are unchanged** — only the `.dmg`'s
contents differ (bundle instead of bare binary). `candidate_bundle.py`,
`release.yml` and `release-policy.json` therefore needed no edits at all, which
kept a user-facing fix off the release chain's critical logic. The signing
receipt gained a `macos-universal-app` entry; the identity check reads assets by
key (`.get`), so adding one is safe. The `.tar.gz` still carries the bare signed
binary for command-line-only use.

**`minicon install-cli` / `uninstall-cli`.** A bundle keeps its executable at
`Contents/MacOS/minicon`, off `PATH`, but MiniCon is also a control CLI. These
symlink it into a prefix (`/usr/local/bin` by default, `--prefix` for a
directory the user owns, needing no sudo) and **refuse to replace or delete
anything that is not a symlink**, so they can never consume a package manager's
binary or a hand-placed file. Covered end to end in `tests/minicon_control.rs`.

## Lessons

- **six-cell caught a self-inflicted failure, and the gate was right.** The
  first six-cell run came back `FAIL: 2` — `minicon_alignment`'s
  `referenced_repository_paths_exist` rejected the new `AGENTS.md` text because
  it named files in *another* repository (the skills hub). The fix was to use
  the convention the gate already documents: a `~`-prefixed path means "outside
  this clone, not a claim about it". That also made the reference more useful,
  since skills are registered under `~/.claude/skills/`. No gate was relaxed.
- **Do not pipe a gate's output through `tail`.** The first six-cell run was
  launched as `... | tail -12`, which discarded the failure detail and forced a
  detour through `target-six/receipt.json` and the per-cell logs to find out
  what broke. Capture the whole log.
- The Defender court receipt's UTF-8 BOM (a v0.1.15 lesson) is now handled
  inside the driver script rather than worked around by hand.
