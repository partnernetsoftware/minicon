## What shipped

### The mouse can reach Windows terminal programs (opt-in)

The owner reported that grok CLI never saw clicks inside MiniCon on Windows,
while the **same program in a plain `cmd.exe` window responded correctly**, and
macOS was fine throughout. That comparison is what located the fault.

conhost is the program; **ConPTY is a mode of it**, and they are not the same
path. A `cmd.exe` window is classic conhost: it owns a real console window and
translates nothing, so mouse input is native. A third-party terminal has no
choice but ConPTY, where conhost runs windowless and translates VT over pipes —
and it must translate rather than forward, because the same console also serves
`ReadConsoleInput` clients. Measured on the court, in both directions:

- **outbound**: the child's `ESC[?1000h` / `ESC[?1006h` never reaches the host,
  so the host never learns the program wants the mouse;
- **inbound**: the host's SGR reports are discarded, while plain text traverses
  the identical pipe.

**Correction, recorded after the release.** The history first claimed upstream
confirmed this as ConPTY's own gap. Checking the referenced items properly says
the opposite: microsoft/terminal#376 "[Conpty] Add support for mouse input" was
**closed 2021-05-27**, PR #9970 "[Conpty] Pass through request for mouse mode to
the Terminal" was **merged 2021-05-07**, and PR #6309 (win32-input-mode) merged
in 2020. ConPTY has carried the mouse for years and Windows Terminal shipped it
in 1.9. The measurements above are real, but the cause is therefore on our side
— `ENABLE_MOUSE_INPUT` appears nowhere in our ConPTY setup — or the probe's
method was wrong. Treat "ConPTY cannot do mouse" as **disproven**; the open
question is what our ConPTY path fails to enable. The classic console remains
the default because it is the path proven to work on a real machine, not
because ConPTY is incapable.

The fix is to stop going through ConPTY for users who need the mouse. The
classic console-agent path is now reachable from the product: put
`{"console_agent": true}` in `minicon.json`. In the platform crate that path
gained SGR-mouse decoding (`ESC [ < code ; col ; row M|m` →
`MOUSE_EVENT_RECORD`, with buttons, movement, wheel delta and Shift/Alt/Ctrl),
plus a poller that watches `ENABLE_MOUSE_INPUT` on the console and synthesises
the DECSET announcement into the output stream so the terminal side learns the
program wants the mouse. The closed loop was proven on the court with a
`ReadConsoleInput` probe — a byte-reading probe cannot see these events at all,
which is itself the point: the records never appear as stdin bytes.

It is **opt-in** rather than the default because the classic path is a different
implementation from ConPTY and deserves real-world mileage first. The owner will
report from his own Windows machine before the default is reconsidered.

The sharpest diagnostic to keep: the `route` field in a `send-mouse` reply.
`selection` means the host never saw the child's mouse DECSET; `application`
means the host forwarded it.

### A Quit button on the greeting page

With no tabs open the window could not be closed at all: `CloseRequested` was
swallowed by the empty-workspace early return in `ConApp::event`, so the close
button did nothing and killing the process was the only way out. The greeting
page now offers `[Quit MiniCon]` below `[New Tab]`, **and** the window close
button works again — the owner asked for both ("都要修"), and they were the same
early return.

### The Linux download lost an unused accessibility stack

MiniCon shipped an AT-SPI publisher built for a sibling product's
computer-use automation. MiniCon has no such consumer: its automation story is
the `--control` CLI, which an AI or script can drive directly. Removed, along
with the AT-SPI test that drove the composer through it.

**Correction worth recording.** The first measurement claimed a 43% reduction —
that compared *unstripped* builds, which is not what anyone downloads. Against
the artifact users actually received in 0.1.17 (`6,014,128` bytes) the stripped
0.1.18 binary is `4,519,696`: a **24.8%** reduction. The release notes and the
README size table carry the honest number; the a11y commit message still carries
the wrong one and is left as-is rather than rewriting published history.
