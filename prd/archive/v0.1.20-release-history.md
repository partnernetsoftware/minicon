# v0.1.20 release history

Status: **released.** Public Release `v0.1.20` is published (not a draft, not a
pre-release), dual-signed as always. The window became something the process can
put down and pick up again, the tab sidebar can collapse, and `MiniCon.app`
finally has an icon.

## What shipped

### The window is detachable, and can be absent from the start

`detach-gui` releases the window while the process, its sessions and the control
endpoint keep running; `attach-gui` builds one again with the scrollback intact;
`--headless` starts with no window at all. Verified end to end: a headless
process runs a shell, answers `send-text` and `capture-pane`, then grows a real
1920×1200 window on attach with its marker still in the scrollback.

**The product boundary was amended rather than worked around.** It said the
`--control` endpoint "lives only as long as its GUI"; it now says the endpoint's
lifetime is the **process**. What that does not admit is written next to it: no
server, no daemon, no listening network interface, no persistent workspace, no
session sharing or discovery, no background auto-start. A MiniCon without a
window is the same single process, minus its window.

Two things had to be true for that to work, and the first attempt at each was
wrong in an instructive way:

- **A detached process still needs loop turns.** Everything in the window
  application trait is handed a window, so with none the loop simply parked: the
  endpoint accepted connections and never replied. A process alive but deaf is
  worse than one that exited. `PixelWindowApplication::detached` now runs once
  per turn with no window, draining PTY output and answering every request —
  served where the verb needs no window, refused **by name** where it does.
- **The attach handle must not hold the window.** It first came off a
  `PixelWindow`, which meant holding it across a detach would have kept the
  native window alive and made the detach a lie — and a process that started
  headless had no window to take one from. The handle is now built from the
  runner's own state.

`list-tabs`, `capture-pane` and `send-text` moved into a shared windowless path
rather than being duplicated, so each verb keeps one implementation and a
detached session stays inspectable.

**The memory claim is withdrawn.** Detaching was partly justified by saving
memory; it does not, on macOS. Release build, one shell session: 84,432 KB
attached, 84,512 KB detached, 84,880 KB reattached, 84,752 KB detached again. A
debug build agrees. RSS counts shared framework pages a released surface does
not give back and the allocator does not return freed pages on `Drop`, so a
saving could be hiding — but hiding is not measured, and the claim goes rather
than gaining a caveat. What survives is demonstrated instead of argued: a
session that outlives its window, and a stable attach point for a future mobile
client.

### The tab sidebar collapses to a rail

A toggle sits at the far right of the sidebar header — the control that takes
the column away belongs nearest the column edge — with `Ctrl+Shift+B` for the
keyboard. Collapsed, each tab shows its `@ID`, the same handle the control CLI
uses, so what a user reads is what they would type; hovering floats the full
title over the terminal. Depth, branch lines and the per-row close button are
dropped, because none survives a 44dip column legibly and a half-drawn close
button is worse than none. The three header controls stack instead, so New and
Settings stay reachable.

Measured, not assumed: viewport x 448 → 88, width 1448 → 1808, grid 90 → 113
columns, and expanding restores all three exactly. The collapsed layout joined
`LAYOUT_SWEEP`, where the existing extreme-geometry test immediately caught a
`pad * 2` overflow in the new tool sizing.

### MiniCon.app has an icon

Running it from the `.dmg` left a blank square in the Dock: the bundle carried
no `.icns` and no `CFBundleIconFile`. The icon matches the existing
`assets/minicon.ico` rather than inventing a second identity, and carries
simplified art at 16/32px because two panels and two prompts turn to mush there.
Generated deterministically by a standard-library script; the packaging step
asserts the file is present and the plist key is right, so it is a gate rather
than a hope.

### Windows mouse: the documentation stopped being wrong

Two explanations shipped in 0.1.18 and 0.1.19 were withdrawn, and the README
stopped telling users to set a config key 0.1.19 had deleted. The settled
statement names a version: **the ConPTY that ships with Windows mistranslates a
mouse report for programs that read console events**, delivering one keystroke
per character; Microsoft's redistributable does not. That is why such a program
answers the mouse in Windows Terminal, which carries its own console host.
MiniCon now uses a `conpty.dll` + `OpenConsole.exe` pair placed beside the
executable, and `--status` reports which host actually served the session —
including the case that silently lies, a DLL without its companion.

**It does not yet fix the mouse inside MiniCon**, and the README says so. With
the fixed host demonstrably in use, a record-reading child still receives
keystrokes, while a test program driving the same layer in the same directory
with the same bytes receives its mouse. Ruled out, each 3/3 on the interactive
court: creation flags, pipe kind, DSR bootstrap, the DA reply and motion report
MiniCon writes, the environment block, resize, click timing, console ownership,
and the child's own console mode. The discrepancy is open.

## The instrument, which mattered more than any finding

Windows commands were reaching the court through the QEMU guest agent, which
runs them in **session 0** — not a session any user has. The identical ConPTY
probe there returned a mouse record on one run and 20 key events on the next,
and a nine-row elimination table had been built on such single readings before
the contradiction surfaced. `utm-court` gained Windows `interactive-exec`
(session 1); every measurement above repeats 3/3 or 4/4.

The rule that cost: **establish repeatability before comparing.** A chain of
one-shot A/Bs on a noisy instrument is worse than no data, because it reads like
proof.

## Gates added

- `referenced_repository_paths_exist` now covers `PRD.md`, `prd/` and `plan/`.
  Those are the documents an agent is told to start from, and one had pointed at
  a plan archived releases earlier. Archives stay excluded: a release history
  records what was true then, and rewriting it to keep a link alive would
  falsify the record.
- A manifest gate refuses a local `path =` override. 0.1.20's first build failed
  on exactly that — correct while local, invisible once pushed, fatal only in
  CI.
