## What shipped

- **Windows Latin text in a Latin face.** On the owner's machine
  `minicon --status` reported 新宋体: the raster adapter's coverage-ordered
  family list put NSimSun first, and it measures as a perfect dual-width grid
  face, so every Latin letter was drawn in a Song face. A Latin face now sets
  the cell (Cascadia Mono, else Consolas) and CJK faces are created at twice
  its cell width so full width stays exactly two cells.
- **DirectWrite-style blending**, ported from Windows Terminal's
  `DWrite_GrayscaleBlend` (MIT): white text at half coverage inks 178/255
  instead of 128.
- **A per-size rasteriser choice.** Neither GDI nor DirectWrite wins at every
  size. Against the outline drawn at 8x and box-filtered down, DirectWrite is
  about twice as close at 12-16 px and GDI nearly exact from 18 px up, so each
  size measures and keeps the closer one.
- **Copy-on-select inside programs that own the mouse** (Claude Code, vim,
  htop): the span a left-drag covered is copied before the release is passed
  on.
- **Clipboard length in the status bar**, re-read only when a system counter
  (`GetClipboardSequenceNumber`) moves or MiniCon itself writes.
- **macOS input-method indicator** inferred from what the input method does
  with the next letter: macOS has no public API for an IME's internal
  Chinese/English mode.

The owner's verdict on the text after the face and blend changes: "acceptable"
and then, after the per-size rasteriser, "the text should be fine now".
