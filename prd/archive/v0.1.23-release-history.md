## What shipped

Four Windows fixes a user can feel, all found or confirmed by running the full
Windows suite in a real desktop for the first time.

- **Scrolling back through shell output works again.** MiniCon hosts the
  classic Windows console by default, and that path kept no history: the
  console buffer was exactly the window's height, so rows that left the screen
  were gone before MiniCon saw them. The buffer now keeps 500 rows above the
  window and each scroll is mirrored into the host's scrollback
  (agenterm `1fe5dc175`, `487b70a11`).
- **`Ctrl+V` pastes in the terminal.** It reached the shell as 0x16 and
  `cmd.exe` printed `^V`; only `Ctrl+Shift+V` pasted. Reported by the owner
  against 0.1.22.
- **A collapsed tab rail selects instead of closing.** One icon wide, the
  close box covered most of a row. Also reported against 0.1.22.
- **`--status` names the console a run will really use,** and accepts
  `--feature conpty` so the other path can be asked about. It used to answer
  "conpty" while every session ran on the console agent.

## What the local rounds found

- **A hosted Windows runner has a real logged-in desktop** (`runneradmin`,
  session 2, Active, 1024x768) and MiniCon's GUI journeys run on it. The local
  UTM court had been assumed necessary for those; it is now the fallback, for
  the Defender scan, legacy images, offline work and long debugging.
- **The court became usable.** HTTP transfer instead of QGA copy (4 MB: 19 s
  -> 2 s; a Windows `test` stage 227 s -> 72 s), resume from an in-memory
  pause (5-9 s against ~100 s cold), a push ledger that skips bytes the guest
  already holds, and every external wait bounded after two rounds sat for an
  hour on a queued runner.
- **Three Windows-versus-Unix differences** were separated from defects: a
  program that cannot start arrives as a child that exited (251), ConPTY
  forwards viewport changes rather than bytes, and deleting a running image
  only marks it delete-pending.
