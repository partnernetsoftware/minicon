## Product change

- `window-enum` now implies `process-spawn` in `agenterm-platform`. The Linux
  app inventory spawns a breakaway visible child to attach to a foreign
  window's session; without the feature edge a Linux cross-build failed on
  `crate::process_spawn` while a Windows or macOS host build never noticed.
  Fixed at agenterm `7036c239`, and minicon's pin moved to that revision.

## Local qualification performed on a Windows host

This release was prepared on an x86-64 Windows host. That machine can build and
run the two Windows cells; it cannot produce the macOS cells (they need the
Apple SDK and a Mach-O linker) and it cannot link the Linux cells (that needs a
Linux sysroot via `zig`, and `zig` on Windows hits a command-line length limit
with this crate graph's link line). Those four cells therefore remain the
responsibility of the six native runners in `six-grid-runtime.yml`.

| Cell | Local build | Command | Receipt |
| --- | --- | --- | --- |
| `win-x86_64` | built | `./scripts/build.sh release` | `target/release/minicon.exe`, `IMAGE_FILE_MACHINE_AMD64` |
| `win-aarch64` | built | `cargo xwin build --locked --release --target aarch64-pc-windows-msvc` | `target/aarch64-pc-windows-msvc/release/minicon.exe`, `IMAGE_FILE_MACHINE_ARM64` |
| `lnx-x86_64` | blocked here | needs `zig`/`cargo-zigbuild` on a Linux or macOS host | — |
| `lnx-aarch64` | blocked here | needs `zig`/`cargo-zigbuild` on a Linux or macOS host | — |
| `osx-x86_64` | blocked here | needs Apple SDK + Mach-O linker | — |
| `osx-aarch64` | blocked here | needs Apple SDK + Mach-O linker | — |

Host toolchain note: the Windows MSVC install on that machine has no ARM64
component, so the ARM64 cell is built with `cargo-xwin` (which supplies the
ARM64 SDK and CRT) and `lld-link` from the Rust toolchain rather than MSVC's
`link.exe`. `cargo xwin` and `cargo-zigbuild` were installed for this; `zig` is
required only for the Linux cells and is not present.
