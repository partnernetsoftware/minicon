## Independent post-publish smoke test

`.github/workflows/release-smoke-test.yml` (new, `workflow_dispatch`-only,
read-only against an already-published tag) downloads the real `v0.2.1`
Release assets on each OS's own native GitHub-hosted runner, verifies their
published SHA-256, and runs a black-box check against the exact bytes an end
user gets. First dispatch (run `36252954567`) passed on Windows but failed on
Linux and macOS from two path bugs in the smoke-test script itself, not the
shipped binaries (the codesign/checksum steps upstream of each failure were
already green) — see
`.claude/skills/run-reputation-and-release/references/troubleshooting.md`
("Post-publish: verify the actual downloaded bytes") for the fix. Re-dispatch
after the fix (run `36253229668`, commit `309d693`) passed on all three
platforms: Linux and Windows binaries run `--status`/`--version`; the macOS
`.dmg` passes `codesign --verify --strict --deep` and `spctl` Gatekeeper
acceptance (Notarized Developer ID) before the mounted `.app`'s binary passes
the same checks. This independently confirms the published v0.2.1 assets are
what a real end user's download/extract/run flow requires, beyond the release
chain's own internal receipts above.
