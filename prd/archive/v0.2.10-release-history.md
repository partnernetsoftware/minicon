## Scope

One outcome, stated before any code was written (`plan/plan-v0.2.10.md`):
**ordinary output stops re-rasterising the whole window** — the root-cause
fix for the owner-reported flashing (总是感觉闪屏).

1. **`{GATE-FORK}` — the vendored `vt100` fork's damage oracle is now run by
   the test gate** (`e566635`). The fork is a `[patch.crates-io]` path and
   deliberately not a workspace member, so `cargo test --workspace` never
   reached `assert_damage_covers` — the only check that catches an
   under-reporting damage range. `scripts/build.sh test` now also runs the
   fork's own suite from its own manifest, scoped to `--lib` (measured 11/0
   before any contract change; 12/0 after).
2. **`{SCROLL-DAMAGE}` — a scroll damages its provable region band, not the
   window** (`7f21e48`, per `plan/plan-scroll-damage.md`). `scroll_up`/
   `scroll_down` mark `[scroll_top, scroll_bottom]` instead of `mark_full`;
   `GridDamage`/`ScreenDamage` gain `scrollback_changed` (the scrollbar thumb
   is drawn outside the row band and was previously repainted by accident);
   `src/terminal.rs` consumes it via `mark_scrollbar_bounds`; the
   exact-visible-cell oracle captures `scrollback_depth` in its snapshot.
3. **`{AMPLIFIER-W}` — the Windows `con` path's blanket upgrade of a partial
   candidate to a full frame is removed** (`ad00f39`). A static audit showed
   both product painters clip every write to the candidate bounds and the
   present copies exactly the WM_PAINT update region.
4. **The root cause the removal exposed — and the fix** (`9892242`). The full
   workspace gate run after the removal failed the registered black-box
   journey `controlled_terminal_click_keeps_native_pixels_stable_outside_
   local_feedback` (before=15425, after=13541 visible native pixels): the
   removed guard had been masking a genuine GDI defect, not a painter defect.
   On this host, `StretchDIBits` mishandles a sub-rectangle source whose top
   is not row 0 — it returns the full DIB height (a 345-row request at
   source y=216 answered `copied=561`) and blits DIB-origin rows over the
   exposed band. Presents whose source starts at y=0 mis-blit invisibly (the
   rows land on the same destinations), which is why the bug survived every
   prior test. Every corrupted present then failed `validate_stretch_copy`,
   invalidated the frame, and forced the next one full — the
   corrupt-partial/repair-full cycle the owner reported as flashing. The fix
   hands GDI a self-consistent sub-DIB (bit pointer at the exposed origin,
   header describing the exposed extent with full stride); measured 345/345
   where the old form returned 0 (which additionally closed the window
   through apply_directive's error-exit policy), 441/441 where it returned
   561, and zero Failed outcomes across a full present run. The journey is
   green with the guard still out.
5. **{AMPLIFIER-T} deferred to 0.2.11** with its design note in the plan: on
   a Transient-retention host the frame contract itself rejects partial
   commits; narrowing it means a retained second canvas, evidence via CI
   `xvfb-run`. The reported flashing is a Windows-host report; this version
   delivers the outcome on that host.

## Notes for the next chain

- **A dispatcher-side input bug worth recording**: reputation attempt 1
  (38596572053) failed in 13 seconds at `base64: invalid input` because the
  `qualification_base64` input carried the *file path* instead of the file
  *contents* (a Windows path with backslashes is very much not base64).
  The re-dispatch with `$(cat file | tr -d '\r\n')` passed. Re-dispatching
  reputation is always safe: it binds to the Candidate and the pinned
  branch, never to `main`'s HEAD.
- The 0.2.9 lessons all held this time: no pushes to `main` mid-chain, the
  dry run before the publish, the throwaway `candidate-src-0.2.10` branch
  deleted immediately after Promotion (both sides), every `-f` input name
  verified against the workflow files before dispatching, and
  `release-policy.json` read first (`signing.mode=required`,
  `reputation.mode=defender`).
- The local-gate lesson that made this release possible: **the authority is
  `./scripts/build.sh test` in full, not a hand-picked subset of suites.**
  The GUI-present defect (and the guard that masked it) lived in the
  black-box suite an earlier session had skipped while calling the gate
  green. The one `network_http` loopback failure seen mid-gate was a sandbox
  artifact (injected `HTTP_PROXY` env); it passes with the proxy vars
  removed — worth remembering before suspecting the product.
