# v0.2.15 release history

## User-visible result

The release clarifies MiniCon's reusable module boundaries while retaining the
three public crate names and historical import paths. Core owns the tree and
numeric rules; UI-core and platform retain compatibility re-exports. Core's
dependency-bearing composer/json/keymap modules are default-enabled features;
minimal consumers opt out, and consumers already disabling defaults must now
explicitly enable the APIs they need. The legacy host-newline helper remains
compatible; new callers can choose the newline form explicitly.

The release includes the fourth, persisted Dark theme and fixes the Windows
console mirror treating unchanged blank/uniform frames as newly scrolled rows.
Build-state cleanup also uses a non-signaling Windows liveness probe; the old
Python signal-zero probe could terminate the process it intended to inspect.

## Qualification and its limits

The final-source Windows x86_64 canonical workspace-plus-vt100 gate returned
zero: 454 product units, 38 ordinary GUI cases, 11 control cases, 106 core
units, 460 platform units, 55 UI units and 12 fork units pass, as do the other
registered workspace/process/policy suites. These are named suite counts,
not an aggregate that double-counts nested process-test children. The real
GitHub release-API test separately passes on Windows x86_64. Evidence remains
under ignored `target/v0215-release/` (`full-test-0ac2d7e.log`,
`full-test-0ac2d7e-summary.json`, `live-release-api-0ac2d7e.log`). Final fmt
and workspace/all-target Clippy pass. Earlier script self-tests and actual
source guard/API/feature/kernel negative controls are recorded in the plan.

The native development workflow executes core, default UI, isolated minimal
consumer, alignment, GUI/control and sustained throughput on all six cells,
plus Windows console-agent suites. It does not execute every root/platform
unit or every optional feature on every cell merely because all targets build.
The final Windows ARM receipt contains 38 GUI passes/one manual IME ignore and
11 control passes, including the complete multi-tab journey. Windows x64 also
has 11 control passes. All six development cells retain the throughput floor.
Windows console-agent output is a known producer workload observed through a
screen-buffer mirror, not a claim that the PTY counter drained all 32 MiB.
Final macOS x64 throughput is 1,352,424 B/s against 1,310,720 B/s; it is a floor
pass, not evidence of a broad performance improvement.

Manual native IME and the platform measurement-only court remain excluded from
ordinary automated qualification. A Windows live HTTPS result does not certify
live HTTPS on all Unix cells. Default UI and minimal consumer results do not
certify every optional native capability. Local VM courts remain independent
of hosted native evidence. Dark-theme screenshot evidence remains scoped to
the documented Windows court. Carried RSS/readability/TUI debt stays with its
existing owner; this release does not claim those debts are all resolved.

## Why qualification took longer

Qualification exposed one production mirror defect and several fixture
assumptions: shell echo versus executed output, history not observed before a
wheel assertion, actual desktop geometry, cold PowerShell/C# readiness,
timestamp ordering and shared clipboard contents. The first wheel mutation
stopped early at a focus failure and was invalidated; the corrected mutation
reaches and fails the original one-notch assertion. Disabling actual async
clipboard delivery fails its original marker assertion with the host alive.
Temporary production mutations are restored before final qualification.

On superseded source `78b7eed`, macOS x64's first throughput observation was
1,256,142 B/s and failed the unchanged floor. A single same-source job repeat
passes at 2,339,276 B/s; retain both observations. Both Windows control courts
failed at asynchronous clipboard input. The final fixture serializes the two
clipboard journeys and captures host stderr/exit status. Their final native
passes qualify the corrected fixture; they do not retrospectively prove the
exact cause of the earlier x64 host exit.

Final pack job `117720714534`: cache restore 75 seconds, tooling 71, packing
134, cache post-processing one. A previous cache-miss run spent 83 seconds in
cache saving; do not describe that as an unconditional cost. Full Windows GUI
cost still includes a sleeping notes driver and fixed diagnostic watcher. The
post-release [0.2.16 design](../../plan/plan-v0.2.16.md) addresses selection,
composition, fixture lifetime and measurement while preserving full gates.

## Separate ownership

The requested Win+R administrator checkbox belongs to MiniCon WinMgr's existing
Run dialog (its Run PRD R8), where it is recorded as unimplemented. It is not a
MiniCon 0.2.15 capability. AgenTerm's incremental consumer migration is a
separate working-tree change at its existing immutable dependency revision; it does
not inherit MiniCon's runtime qualification or silently move its pin.
