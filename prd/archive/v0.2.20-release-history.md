# v0.2.20 release history

## User-visible result

[v0.2.20](https://github.com/partnernetsoftware/minicon/releases/tag/v0.2.20)
is public. **The owned Rust console (`minicon-console`) is now the Windows
default backend**: one process per tab instead of three, no extra
`conhost.exe`, every byte of output delivered to the terminal and its
scrollback. Rollback is one word — `--feature console-agent`, or
`"backend": "console-agent"` in `minicon.json` — and `--feature conpty` still
selects ConPTY; `minicon --status` names the backend a run will use.

Fixed on the way, each with a failing-first test:

- Git for Windows `less`/`bash` printed nothing under rust-console (the MSYS2
  runtime gives up when `GetConsoleWindow` fails) — a message-only
  pseudo-console window now answers it.
- Mouse input reaches console readers under rust-console (it was dropped).
- Window resizes notify TUIs such as codex-cli even without
  `ENABLE_WINDOW_INPUT`, as conhost does, so they re-lay out.
- A program that cannot start stays the tab's failure instead of ending the
  window.
- A single console write over 1 MiB no longer hangs the session.
- Programs run in a tab no longer inherit MiniCon's own backend forcing.
- New per-row "+" (new child) button between edit and close in the tab tree.
- The owner's file-tool misalignment report was attributed to the classic
  backend's wire (it re-emits half-overwritten wide characters); the default
  backend renders it correctly.

Behavior owners: [terminal backend selection](../PRD_02_24_con_terminal.md#pty-backend-selection),

## Qualification scope

Local gate on the release source (Windows x64 20348): fmt, clippy
`-D warnings` with default features and with `--no-default-features`,
`./scripts/build.sh test` 34 suites / 1465 passed — every GUI journey now
runs on the rust-console default. dev-loop-crosscheck on the final code:
lnx-x86_64, lnx-aarch64, osx-aarch64 and osx-x86_64 passed every suite
(39792228284); the Windows cells passed everything apart from the two named
pre-existing flakes below, including the native `rust_console_pty` suite and
the 32 MiB throughput journey on a release product build (win-x86_64
10.6 s, win-aarch64 9.5 s; budget 30 s).

Decision courts (local, Windows x64, recorded in PRD 24 / 24.01): three
`cmd` tabs cost 4 processes / 35.4 MB on rust-console versus 10 / 99.4 MB on
the console agent, with equal-or-better echo latency and zero orphans after a
crash-shaped kill; the visible three-agent start-and-resize court (Claude
Code 2.1.304, Codex CLI 0.162.1, Grok Build 1.0.62) rendered and re-laid out
correctly on current source. The visible matrix was not rerun against the
signed Candidate bytes; the packaged six-cell executions are the
exact-artifact evidence.

## Known open items (named, not hidden)

- **G4** — a heap corruption (0xC0000374) in the GUI host, hit by one
  control journey at its async clipboard paste step, about half the time on
  the GitHub Windows runners and occasionally locally. Present since at
  least 0.2.18 on the classic backend too; not in the release chain's
  courts; next step is a page-heap run from an elevated shell.
- **G6** — two native rust-console tests stall at their FreeConsole
  ("disconnect") variant on the new Windows runners while output is
  deliberately unconsumed. Measured on the published v0.2.19 source at
  4 of 4 cell-runs and on pre-flip 0.2.20 source at about half, so it
  predates this release; a MiniCon GUI always consumes output, which bounds
  the product impact.
- The provider's default console input mode reports `0x7` where conhost
  reports `0x1F7`; four rarely used L3 queries remain unimplemented
  (PRD 34 names them).
