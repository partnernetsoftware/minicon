# v0.2.6 release history

Published 2026-10-13 under the owner's explicit publication authority (the owner
named "run the six cells on GitHub CI; if it passes, arrange the 0.2.6 release").
Public release: https://github.com/partnernetsoftware/minicon/releases/tag/v0.2.6
Source: `c8d70a55fb3e7b1da81225c3296941a5385fb00f`.

Scope: the first cut of the **right-side collapsible sent-history panel** the
owner asked for (GitHub issue #3). A panel lists the newest lines the composer
has sent (newest first) and refills the composer when a row is clicked, through
the same recall contract the Up/Down history keys use — so a clicked row and a
recalled line at the same offset are the same line, over the composer's one
sent-history store. It takes a real column and the terminal is re-inset (a new
`content_right_px` threaded through the grid, viewport and scrollbar geometry),
never overlaid; a blank area below the list is reserved for future
`{LOOP}`/goal controls. The single sidebar toggle became a **pair** of chrome
toggles — the header now reads left-to-right as the columns they control — and
the two glyphs were differentiated (a solid sidebar/panel bar). `Ctrl+Shift+H`
was added to the settings shortcut list. `ui-snapshot` gained `history_panel`
and the `panel_toggle` rect. Also included: a repo-hygiene documentation pass
(six shipped/superseded plans archived, an explicit `[no]` non-goal marker split
out of `[-]`, a `[✓]` and an expanded home path fixed) and a Linux-only test
compile fix (`x11_clipboard.rs`'s test module was missing two imports, so the
Linux `lib test` target had never compiled).

Explicitly **not** in 0.2.6: the notes scratchpad (issue #5) and the
"check for updates" flow (issue #4), which moved to `plan/archive/plan-v0.2.7.md`.

## Notes

- The chain was driven from a Windows host with `gh` (scopes `repo`, `workflow`)
  using the dispatches `scripts/release.sh` encodes. The one stop was the
  expected one: the script's `1/8 bump` step had nothing to commit because
  `Cargo.toml` and `release-policy.json` were already at 0.2.6 in an earlier
  commit, so steps 2–8 were driven by hand with `source_sha` pinned to
  `c8d70a5`. This is the same trap 0.2.5 hit; it is now recorded in the release
  skill's "Fast path", in `scripts/release.sh`'s header, and in
  `prd/PRD_02_27_con_delivery.md` § "Driving the chain".
- `main` never moved during the chain (every gate asserts
  `source_sha == GITHUB_SHA`); `reputation.yml` and `release.yml` ran on a
  throwaway `candidate-src-0.2.6` branch pinned at `c8d70a5`, deleted after.
- Local gates before the push were green: `cargo fmt`,
  `cargo clippy --workspace --all-targets -- -D warnings`, and the test suites
  except one pre-existing failure (`controlled_wheel_moves_the_real_scrollback_
  offset_up_then_down`, recorded in `plan/plan-repo-hygiene.md`, reproduced on
  the pristine tree).
- The Linux cross-check (`cargo zigbuild --workspace --all-targets --target
  x86_64-unknown-linux-gnu`) is what surfaced the `x11_clipboard.rs` test-module
  imports; macOS was not cross-checked locally (the osxcross + Apple SDK
  toolchain `scripts/six-cell-qualify.sh` uses is not on a Windows host) — the
  six-cell pack in CI is the macOS evidence for this release.
- Post-publish smoke test (`release-smoke-test.yml`, run 38337042902) downloaded
  the real `v0.2.6` assets, re-checked their published `.sha256`, extracted and
  ran `--version`/`--status`: PASS.
